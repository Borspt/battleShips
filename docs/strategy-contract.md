# Контракт оболочки и стратегии · версия 1

Предложение для согласования Музробом и Борисом. Реализовано в текущей интеграционной ветке.

## Общий принцип

Оболочка — единственный владелец актуального состояния. Она применяет сообщения сервера,
передаёт копию `GameState` стратегии, проверяет решение и отправляет JSON.
Стратегия не открывает WebSocket и не отправляет команды платформе.

Стратегия получает полное доступное состояние при каждом запросе. Она должна уметь работать
после перезапуска без памяти предыдущих вызовов. Изменения переданного `state` не возвращаются оболочке.
Отдельный `on_result()` не нужен: результат очередного действия уже включён в следующий `state`.

## Типы

Импорт: `from battleships.model import Action, Cell, GameState, Rules`.

- `Cell(row, column)` — строка, столбец, от нуля. Не `(x, y)`.
- `Rules.fleet` — кортеж длин всех кораблей, например `(4, 3, 3, 2, 2, 2, 1, 1, 1, 1)`.
- `state.shots` — история `(Cell, result)` наших выстрелов в порядке поступления.
- `state.opponent_shots` — доступные выстрелы соперника; может быть пустой в BIRD_BOX/SPEEDRUN.
- `state.ships` — принятая собственная расстановка; в SPEEDRUN её нет.
- `state.bonuses` — остаток использований; `bonus_results` — полученные результаты с `requestedCell`.
- `state.opponent` — информация из `MATCH_STARTED`; после восстановления может быть пустым словарём.
- `state.move_number`, `shots_left`, `shots_left_in_turn` — последние значения сервера.
- `state.legal_targets()` — допустимые необстрелянные клетки с учётом геометрических исключений.
  `DEFENDED` остаётся допустимой целью. Метод не использует результаты информационных бонусов.

## Расстановка

```python
def place_ships(self, rules: Rules) -> list[list[Cell]]:
    ...
```

Каждый внутренний список — один прямой непрерывный корабль. Длины должны совпадать с `rules.fleet`.
Оболочка проверяет границы, касания, пересечения и длины. В SPEEDRUN метод не вызывается.
На расчёт основной расстановки отводится до 1 секунды, затем используется резервный генератор
в пределах оставшегося серверного окна. Принятая расстановка окончательна.

## Выбор действия

```python
def choose_action(self, state: GameState, time_budget_ms: int) -> Action:
    return Action.shoot(Cell(3, 5))
```

Опциональный бонус:

```python
return Action("USE_BONUS", cell=Cell(4, 4), bonus="SONAR")
```

Разрешены DISTANCE, SONAR, SALVO, SHIELD, MINE, если сервер выдал использования.
Для SALVO и SHIELD клетка не нужна. Оболочка дополнительно требует `--allow-bonuses`.
Стоимость бонусов не приходит в WS-состоянии: автоматическую экономическую стратегию нельзя
строить, предполагая постоянную цену. В первой версии бонусы и ставки не используются.

Результат возвращается **за один вызов**. Не возвращать пакет выстрелов даже при залпе:
следующая клетка выбирается после результата и нового `TURN_REQUESTED`.

## Дедлайн и сбои

Стратегия исполняется в отдельном процессе, прогреваемом до подключения.
По умолчанию один вызов получает до 150 мс, с учётом оставшегося времени.
Превышение бюджета, исключение или недопустимый результат приводит к резервному выстрелу.
Зависший процесс завершается; следующий вызов может получить новый экземпляр класса.
Не выполнять сетевые запросы и длительное обучение внутри `choose_action`.

## Обязательные различия режимов

- SCHRODINGER_SHIP: HIT не говорит, остались ли целые клетки именно у этого корабля.
- SPEEDRUN: собственной расстановки нет; основной результат определяется числом выстрелов.
- HUNGER_GAMES: при лимите цель — больше попаданий, даже если весь флот не потоплен.
- DUEL / THREE_MUSKETEERS: очередностью управляет сервер. Читаем `shots_left_in_turn`.
- BIRD_BOX: история противника отсутствует, это не ошибка данных.
- DEFENDED: корабль обнаружен, клетка не повреждена; повторный выстрел разрешён.
- MINE: клетка уже обстреляна; пропуск следующего хода реализует сервер.

## Проверка перед объединением

1. Импорт класса по `module:Class`, конструктор без обязательных аргументов.
2. Валидные расстановки и действия на согласованном наборе состояний.
3. Укладка в бюджет, включая концовки, дефенд и Шрёдингера.
4. Общие тесты: `python -m unittest discover -v`.
5. Диана сравнивает кандидата с предыдущей версией по каждому режиму.
