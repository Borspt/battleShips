# Бонусы: когда применять и окупается ли цена

Снимок цен: DISTANCE 1, SONAR 3, SALVO 4, SHIELD 2, MINE 1 (лимиты 3 / 1 / 1 / 3 / 3). Решающая логика принимает цены параметрами.

Отчёт опирается на два источника, и в тексте они помечены:

- **[Р]** — вывод из регламента и арифметики.
- **[М]** — вывод из моделирования (`sim.py`, 6000 партий). Модель:
  - поле 10×10, флот 1×4, 2×3, 3×2, 4×1, без касаний, в том числе по диагонали;
  - попадание даёт ещё выстрел, потопление объявляется;
  - стрелок работает по карте вероятностей с добиванием и в среднем тратит 55,2 выстрела на флот (σ = 6,9), как наш бот (55,7);
  - соперник — такой же бот без бонусов.

  Результаты [М] — оценка для «нас против равного по силе», а не для конкретного соперника.

## 2. Экономика: проверка формулы Δp* ≈ C/K [Р]

### Обозначения

- X — наши траты за партию, Y — траты соперника.
- E — наше ожидание Elo, E_о = 1 − E — ожидание соперника.
- K — наш коэффициент, K_о — коэффициент соперника.
- G = K·(1 − E) — наш прирост Elo при победе, L = K·E — наша потеря при поражении.
- G_о = K_о·(1 − E_о) и L_о = K_о·E_о — то же для соперника.

### Изменение нашего рейтинга за партию

После Elo каждый платит за свои применения, оплата уходит сопернику. Победитель не уходит в минус, проигравший не уходит в плюс.

```
Победа:    T = X − Y   (чистый перевод от нас сопернику)
           Δ_win  = G − T,                  если T ≤ 0
           Δ_win  = G − min(T, G, L_о),     если T > 0

Поражение: T = Y − X   (чистый перевод от соперника нам)
           Δ_loss = −L + T,                 если T ≤ 0
           Δ_loss = −L + min(T, L, G_о),    если T > 0

Ничья:     Δ_draw = K·(0,5 − E) − (X − Y)   (ограничений нет)

EV(p, X, Y) = p·Δ_win + (1 − p)·Δ_loss      (ничьи в классике пренебрежимы)
```

Бонус ценой C с приростом вероятности победы Δ выгоден, если `EV(p + Δ, X + C, Y) − EV(p, X, Y) > 0`.

### Частные случаи

**Случай 1: X + C ≤ G и Y = 0.** Это обычный случай.

ΔEV = Δ·(G + L) − C = Δ·K − C, отсюда **Δp\* = C / K** при любой разнице рейтингов, потому что G + L = K.

Цена списывается полностью и при победе, и при поражении. Базовая формула верна.

**Случай 2: траты выше прироста за победу (X ≥ G).**

Дополнительный бонус при победе бесплатен, а при поражении стоит C:

ΔEV = Δ·(K + C) − (1 − p)·C, отсюда **Δp\* = (1 − p)·C / (K + C)**.

Пример: K = 10, равные рейтинги (G = 5), после DISTANCE ×3 и SHIELD (X = 5) SALVO при p = 0,5 требует Δp\* = 0,5·4/14 = 14 пп вместо 40. Только в этой зоне тезис «почти бесплатен при победе» верен.

**Случай 3: соперник потратил много.** Если Y − X > min(L, G_о), то при поражении наши траты съедаются из «переплаты» соперника и нам ничего не стоят, пока разница не опустится до порога.

**Оговорка.** Формулы выше предполагают, что ограничения применяются к итогу партии, а не к каждому платежу по очереди. Если платформа списывает по очереди, ответ изменится. Нужно проверить по истории партий со списаниями или спросить организаторов.

## 3. Модель состояния и p(состояние) [М]

### Состояние

- **Флоты:** `h_us` и `h_op` — живые клетки флотов (у нас — флота соперника, по которому стреляем мы; у соперника — нашего).
- **Корабли соперника:** список живых, недобитые попадания, множество согласованных расстановок, если кораблей ≤ 2.
- **Выстрелы и ходы:** остаток выстрелов из лимита, чей ход, ходов соперника с начала партии.
- **Бонусы:** наши остатки и траты X, остатки соперника и его траты Y (по `OPPONENT_BONUS_USED`), активен ли наш щит, стоит ли наша мина.
- **Партия:** модификатор, K, E, цены со старта матча.

### Гонка

В классике исход — гонка промахов.

- R_us — сколько ещё промахов нам нужно до потопления флота соперника, R_op — то же для соперника.
- Если сейчас наш ход, мы побеждаем при **R_us ≤ R_op**. Значит, p = P(R_us ≤ R_op + сдвиг), а бонусы меняют сдвиг или распределение R_us.
- Первый ход партии даёт 52,0 % побед.
- Распределения R по числу живых клеток h берутся из прогонов. Это таблица `cond[h]`, её стоит сохранить в конфиг бота.

## 4. Запросы: выбор клетки и экономия [М]

### Метод

Когда у соперника ≤ 2 корабля и нет недобитых попаданий, бот перебирает все согласованные расстановки оставшихся кораблей. Обычно их от сотен до нескольких тысяч, и перебор помещается в доли секунды.

Для каждой клетки q из 100 бот считает ответ запроса на каждой расстановке и энтропию распределения ответов:

```
H(q) = −Σ_v P(ответ = v)·log2 P(ответ = v)
```

Запрос идёт в клетку argmax H(q), если H ≥ 0,5 бита. После ответа остаются только совместимые расстановки, стрельба идёт по частоте клеток среди них.

### Результаты (2000 эндшпилей, 95 % ДИ)

| Момент | Без запросов, промахов | DISTANCE ×1 | ×2 | ×3 | SONAR ×1 |
|---|---|---|---|---|---|
| Остался 1 корабль | 3,84 | экономит **3,74 ± 0,15** | 3,83 | 3,84 | 1,99 ± 0,15 |
| Осталось 2 корабля | 7,58 | экономит **3,91 ± 0,21** | **7,24 ± 0,18** | 7,53 | 2,35 ± 0,19 |

### Пересчёт в вероятность победы

Политика «два DISTANCE при входе в эндшпиль 2 кораблей» поднимает P(победа) с 52,4 % до 76,3 % (**+24,0 пп**). С одним запросом +12,7 пп, с тремя +24,8 пп, SONAR ×1 даёт +8,1 пп.

Это средняя оценка по всем партиям. Если применять только при p в диапазоне от 0,05 до 0,95, выигрыш на применение выше, а траты в решённых партиях уходят.

### Почему так много

Два манхэттенских расстояния из разных точек дают r + c и r − c, то есть почти однозначно определяют клетку. Расстановка оставшихся одного-двух мелких кораблей схлопывается до единиц вариантов, после чего промахов почти нет: 0,34 на два корабля.

### Чего не мерили

DISTANCE и SONAR в середине партии (≥ 3 корабля) не прогонялись: полный перебор там слишком велик. Нужен прогон с выборкой расстановок (раздел 8).

| 4 | **Уточнена** [Р] [М] | SALVO не «в худшем случае», а практически всегда даёт ровно 2 дополнительных промаха без передачи хода, если партия не кончится раньше. Это 8 пп в начале и 9–19 пп в близкой концовке. Близкая гонка — правильный триггер, но окупается только при K = 40. |
| 5 | **Частично опровергнута** [Р] | `DEFENDED` выдаёт клетку корабля, но обычное попадание выдало бы её же — информационного ущерба нет. Щит отнимает у соперника ровно один ход независимо от того, когда поставлен. Тайминг важен только потому, что ход ценнее в близкой поздней гонке. Ачивка «Щит и меч» — бонус к правилу, не причина. |
| 6 | **Частично опровергнута, оценена** [М] | Перпендикулярные соседи раненой клетки не гарантированно пусты: пусты только клетки поперёк оси корабля и за его концами, гарантированно пусты лишь диагонали, но в них никто не стреляет. Вероятность срабатывания против бота с той же стратегией: случайная пустая клетка — 1,6 %; пустой ортогональный сосед раненой клетки — 26 %; мода промаха по 8 «проигрышам» его хода — 36 % в среднем, 52 % при раненом корабле, 33 % в поиске. Если прогноз детерминирован (p̂ ≥ 0,99, 15 % ходов) — 99,5 %. Калибровка p̂ хорошая: группы 0–0,3 / 0,3–0,6 / 0,6–0,99 срабатывают в 11 / 26 / 49 % случаев. Против бота с другой стратегией это верхняя граница. |
| 7 | **Подтверждена, причина другая** [Р] [М] | При p < 0,05 или p > 0,95 ход стоит < 1 пп. Но цена при уверенной победе не «съедается»: она списывается полностью, пока X ≤ G. |

## 8. Псевдокод

```python
# cfg: цены со старта матча, пороги, таблицы cond[h] и saved[(ships_left, budget)]
def choose_action(st, cfg) -> Action:
    deadline = st.turn_started_at + cfg.turn_budget          # 0.6 с, как у таймера бота
    shot = engine.best_cell(st)                              # запасной выстрел готов сразу
    if not st.bonuses_enabled or st.mode == "OLDSCHOOL" or time_left(deadline) < cfg.min_time_bonus:
        return SHOOT(shot)

    p = win_prob(st, cfg)                                    # P(R_us <= R_op + offset) по cond[h]
    if p < cfg.p_skip_lo or p > cfg.p_skip_hi:               # 0.03 / 0.97: исход ясен
        return SHOOT(shot)

    def gain(dp, bonus):
        C = cfg.price[bonus]
        return ev(st, p + dp, st.X + C, st.Y_exp) - ev(st, p, st.X, st.Y_exp) - cfg.margin[bonus]

    last_shot = st.shots_left is not None and st.shots_left <= 1

    # 1. Информация: в этом ходу раньше всего, она улучшает и обычный выстрел, и залп
    if st.uses["DISTANCE"] > 0 and not last_shot and mode_allows("DISTANCE", st):
        if (st.opp_ships_left <= cfg.dist_max_ships and not st.unresolved_hits) or st.schrodinger_ambiguous:
            q, H = best_query_cell(st.configs, kind="distance", deadline=deadline)
            if q is not None and H >= cfg.min_bits:
                dp = p_after_saving(st, cfg.saved[(st.opp_ships_left, st.uses_spent["DISTANCE"] + 1)]) - p
                if gain(dp, "DISTANCE") > 0:
                    return USE_BONUS("DISTANCE", q)

    if st.uses["SONAR"] > 0 and st.uses["DISTANCE"] == 0 and not last_shot and mode_allows("SONAR", st):
        if st.opp_ships_left <= cfg.dist_max_ships:
            q, H = best_query_cell(st.configs, kind="sonar", deadline=deadline)
            if q is not None:
                dp = p_after_saving(st, cfg.saved_sonar[st.opp_ships_left]) - p
                if gain(dp, "SONAR") > 0:
                    return USE_BONUS("SONAR", q)

    # 2. Защита: щит и мина отнимают ход у соперника
    if st.uses["SHIELD"] > 0 and not st.shield_active and not last_shot and mode_allows("SHIELD", st):
        dp = win_prob(st, cfg, op_offset=+cfg.shield_turns[st.mode]) - p
        if gain(dp, "SHIELD") > 0:
            return USE_BONUS("SHIELD", None)

    if st.uses["MINE"] > 0 and not last_shot and mode_allows("MINE", st):
        cell, p_trig = predict_opponent_miss(st, rollouts=cfg.mine_rollouts, deadline=deadline)
        if cell is not None and p_trig >= cfg.mine_min_ptrig * cfg.opp_calibration[st.opp_type]:
            dp = p_trig * (win_prob(st, cfg, op_offset=+cfg.mine_turns[st.mode]) - p)
            if gain(dp, "MINE") > 0:
                return USE_BONUS("MINE", cell)

    # 3. Залп: последним, после информации
    if st.uses["SALVO"] > 0 and mode_allows("SALVO", st) \
            and not st.opp_shield_active and not st.opp_mine_pending:
        dp = win_prob(st, cfg, us_offset=+salvo_turns(st)) - p    # классика: 2; «Дуэль»: 2 + E[попаданий]
        if gain(dp, "SALVO") > 0:
            return USE_BONUS("SALVO", None)

    return SHOOT(shot)


def ev(st, p, X, Y):
    G, L = st.K * (1 - st.E), st.K * st.E
    G_o, L_o = st.K_op * st.E, st.K_op * (1 - st.E)        # прирост и потеря соперника
    T = X - Y
    win = G - T if T <= 0 else G - min(T, G, L_o)
    T = Y - X
    loss = -L + T if T <= 0 else -L + min(T, L, G_o)
    return p * win + (1 - p) * loss
```

Обработка ответов платформы:

- `BONUS_REJECTED` — сразу `SHOOT(shot)`, бонус в этом ходу больше не пробовать. Таймер не перезапускается.
- `BONUS_RESOLVED` — пересобрать состояние (`configs`, `p`) и снова вызвать `choose_action`. Новый `TURN_REQUESTED` даёт новую секунду.

`mode_allows` — это таблица из раздела 6.

## 9. Взаимодействия

- **Несколько бонусов за ход** [Р]. Каждый бонус не тратит ход, после `BONUS_RESOLVED` приходит новый запрос. Порядок: DISTANCE → (SONAR) → SHIELD / MINE → SALVO → выстрел. Информация первой, потому что улучшает все последующие выстрелы. Защиту можно ставить в любом ходу: она ждёт события.
- **SALVO + DISTANCE.** В классике ценность залпа — ровно 2 хода, и DISTANCE до залпа её не меняет: оба эффекта складываются. В «Дуэли» DISTANCE до залпа увеличивает число попаданий в залпе, а значит и ценность залпа. Запрос — всегда до залпа. Можно ли применять бонус внутри залпа, регламент не говорит — проверить.
- **У соперника SHIELD на старте.**
  - Пока соперник не применил его, ничего не меняем.
  - После `OPPONENT_BONUS_USED: SHIELD` и до нашего `DEFENDED` не включаем SALVO: `DEFENDED` сожжёт залп.
  - Клетку `DEFENDED` бот уже обстреливает снова.
- **У соперника MINE.**
  - После `OPPONENT_BONUS_USED: MINE` не включаем SALVO, пока мина не сработала: в залпе до 3 промахов, и каждый может прийтись на мину.
  - Наш детерминированный стрелок в 15 % ходов предсказуем на 99,5 %, а значит уязвим к чужой мине так же, как чужой к нашей. Если у соперника есть неиспользованные MINE, выбирать выстрел случайно среди клеток с плотностью ≥ 0,95·max, а не по строгому argmax.
- **У соперника DISTANCE.** Его эндшпиль короче на ~7 промахов. Это надо учесть в R_op (`cond` со сдвигом), иначе p будет завышен.

## 11. План прогонов (Борис)

**Протокол сравнения.** Бот против себя, парные сиды: одинаковые расстановки и право первого хода, зеркально в двух партиях. N ≥ 2000 пар на сравнение.

**Метрики:**

- доля побед, 95 % ДИ по Уилсону;
- разность — по парам, ДИ через бутстреп;
- средние траты и ΔEV при K = 40 / 20 / 10 по формулам из раздела 2.

**Статистическая мощность.** Без парности для разницы в 2,5 пп (порог DISTANCE при K = 40) нужно около 6300 партий на вариант: (1,96 + 0,84)²·2·0,25 / 0,025². Парные сиды снижают это в разы.

Прогоны по приоритету:

1. DISTANCE ×2 при ≤ 2 кораблях против отсутствия бонусов — подтвердить +24 пп на нашем движке.
2. Порог для DISTANCE: ≤ 3 корабля против ≤ 2, и куда девать третий запрос (3 корабля, 1 корабль, «Шрёдингер»). Нужна выборка расстановок вместо полного перебора.
3. SALVO, SHIELD, MINE по правилам из раздела 5 против отсутствия, при K = 40. Ожидаемый эффект 2–5 пп на партию.
4. DISTANCE против SONAR против DISTANCE + SONAR в эндшпиле.
5. Режимы:
   - «Голодные игры»: DISTANCE в середине против отсутствия, число попаданий за 40 выстрелов;
   - «Дуэль»: SALVO в добивании;
   - «Мушкетёры»: SHIELD и MINE.
6. Устойчивость: наш бот с бонусами против бота с другой стратегией (случайная охота, шахматный порядок) — как падает срабатывание MINE.

## 12. Доработки симулятора (Диана)

`local_platform.py` бонусов не поддерживает. Нужно добавить:

**Бонусы:**

- `USE_BONUS` → `BONUS_RESOLVED` / `BONUS_REJECTED` с ответами DISTANCE (манхэттен до ближайшей клетки непотопленного корабля) и SONAR (клетки кораблей в 3×3, включая подбитые);
- новый `TURN_REQUESTED` того же хода после бонуса;
- лимиты на матч, отказ при исчерпании и при недопустимой клетке.

**Результаты выстрела:**

- `DEFENDED`: один активный щит, клетка остаётся необстрелянной, ход переходит;
- `MINE`: только на пустую необстрелянную клетку, ход переходит, следующий ход соперника пропускается;
- SALVO: 3 выстрела, попадания не тратят; `DEFENDED` и `MINE` сжигают остаток.

**Сообщения:** `OPPONENT_BONUS_USED` (кроме «Птичьего короба») и `opponent.bonuses` в `MATCH_STARTED`.

**Лимит выстрелов:** списание 1 выстрела за DISTANCE, SONAR, SHIELD и MINE; передача хода, если выстрел был последним.

**Экономика:** Elo с K = 40 / 20 / 10, оплата сопернику с ограничениями из раздела 2, ничья без ограничений. Цена фиксируется на старте матча.

**Режимы:** «Дуэль», «Три мушкетёра» (`shotsPerTurn`), «Голодные игры» (40 выстрелов, победа по попаданиям, ничья), «Спидран», «Шрёдингер» (без объявления потопления), «Птичий короб» (без выстрелов соперника и названий его бонусов), «Казино».

**Арена:** парные сиды, два бота в одном процессе, выгрузка ходов в журнал, таймер 1 с с тем, что `BONUS_REJECTED` таймер не сбрасывает.

**Соперники:** набор ботов разной силы (EASY / MEDIUM / HARD-подобные, детерминированный и рандомизированный по карте вероятностей) — для калибровки p̂ мины и `cond[h]`.

## Источник чисел

`sim.py` (модель стрелка и эндшпиля с запросами), `analyze.py` (гонка, режимы, мины), `eg.py` / `ev.py` (DISTANCE и SONAR). Сид 12345, 6000 партий, 2000–2500 эндшпилей. Модель упрощена:

- соперник играет тем же алгоритмом;
- R зависит только от h;
- сдвиг «+1 ход» одинаково ценен для обеих сторон.

Поэтому числа [М] — ориентир для порогов, а не гарантия; их подтверждают прогоны раздела 11.
