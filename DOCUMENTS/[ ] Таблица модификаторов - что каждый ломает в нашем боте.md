# Модификаторы → что ломается в боте

Проверка 10.10.2026, ~14:10 МСК. Код: присланные `battleships/*.py` (ветка с PR №1 и `boris/probability-strategy`). Регламент: `rules.md`, `protocol-reference.md`, чек-лист «Ловушки регламента».

## Что проверено и чем

- **Раскладка не та, что в задании.** `session.py` + `bot.py` = `battleships/client.py` (+ `worker.py`, `__main__.py`); `engine.py` = `battleships/strategies/probability.py` + `contract.py`. **Этих двух файлов и всего пакета `strategies/` нет среди присланных**, нет и `local_platform.py`, тестов Музроба с локальным сервером, `docs/strategy-contract.md`. Всё о движке Бориса ниже — «гипотеза»; README проекта (`engine.py`, «таймер 0,6 с») устарел.
- **Стенд.** Я написал `bench/protocol_bench.py` — локальную платформу по регламенту, которая гоняет **настоящий** `Controller` из `client.py` с настоящим `StrategyWorker` (сеть заменена прямой передачей сообщений, как в `run_bot`). Движок в прогоне — `BaselineStrategy` Музроба: это и запасная стратегия боевого бота. В каждом модификаторе: 200 партий бот против себя, 20 % партий с обрывом и `MATCH_SNAPSHOT`, у соперника SHIELD и MINE, 200 одиночных стрельб до потопления.
- Итого 1 800 партий и 1 600 одиночных стрельб по 9 режимам (классика + 8): **0 тайм-аутов, 0 отказов команд, 0 ошибок разбора, 0 лишних `PLACE`/`SHOOT`**. Ломается бот на значениях, которых в наших 9 режимах не было (ниже).
- Код команды не менял. Исправления применил к отдельной копии и перепрогнал: всё ниже, что помечено «исправление проверено», закрыто прогоном.

## 1. Вывод

По нашему прочтению регламента ни один из восьми модификаторов сейчас не даёт P0: в прогоне все 1 800 партий доиграны без тайм-аутов и отказов. Опасность одна и общая: `Rules.parse` (`model.py:54-66`) выбрасывает весь `MATCH_STARTED`, если любое поле `rules` равно 0/`null` или `touchRule` незнаком, и бот молча проигрывает партию целиком (в «Спидране» с `placementWindowSeconds: 0` — 6 000 тайм-аутов из 6 000 ходов). Это условный P0 для «Спидрана» и неизвестного модификатора; чинить первым — мягкий разбор правил и сброс состояния (Музроб, ~20 строк, diff ниже).

## 4. Расхождения симулятора с регламентом

`local_platform.py` нет. Есть `simulator.py`/`simulate.py` Бориса (уровень стратегии) и, по README, локальный сервер Музроба в тестах (не прислан). Механику модификаторов `simulator.py` воспроизводит верно — проверил прогоном с подставной стратегией: в DUEL серия одного игрока ≤ 1, в «Голодных играх» 300 из 300 партий `SHOT_LIMIT`, в «Спидране» `SPEEDRUN_FINISHED`. Расхождения:

1. **Нет протокола.** Симулятор вызывает `next_shot`/`on_shot_result` ядра, а не `client.py` → `worker.py` → `contract.py`. Все P0 выше в нём невидимы. Прогон на `simulate.py` не доказывает, что боевой бот сыграет.
2. **Нет времени.** Ни `TIME_LIMIT` (210/90 с), ни тайм-аутов хода, ни правила «Спидрана» «пропуск = выстрел» (`simulator.py:63-70`, `:93-109`).
3. **Флот «Спидрана» случайный** (`simulator.py:78`), а платформа строит его как встроенный `HARD`.
4. **«Спидран» без потопления**: при неудаче обоих симулятор решает по попаданиям (`simulator.py:80`), регламент этот случай не описывает.
5. **Нет `CASINO_ROYALE`** (`simulate.py:19`) и бонусов (`DEFENDED`, `MINE`).
6. **Незнакомый `touchRule` → `no_touching=False`** (`rules.py:46`): расстановка Бориса начнёт ставить корабли вплотную (`placement.py:23`) — обратное безопасному выбору.
7. **Правила зашиты в `Rules.for_modifier`** (`rules.py:53-63`): нельзя проверить, скажем, `shotsPerTurn: 2` или поле 12 × 12 без правки кода.
8. Флагов `-n` и `--solo` из задания нет; есть `--games`, `--modifier`, одиночная стрельба печатается всегда.

Что добавить: взять `bench/protocol_bench.py` (готов, умеет `--modifier` любое имя, `-n`, `--solo`, `--rules-over` JSON, `--reconnect`, `--strategy`/`--strategy-b`) как `local_platform.py` и гонять в нём `battleships.strategies.contract:ProbabilityBot`. Дописать: флот как у `HARD` для «Спидрана», ставки в «Казино», бонусы своей стороны.

## 5. Стратегические заметки для Бориса

Модель «насколько режим превращает перевес в меткости в победы»: наш бот против той же стрельбы без добивания (65,4 выстрела на флот против 58,0, разрыв ~7). n = 400 на режим, шум ±2 пп.

| Режим | Победы | Ничьи | Поражения |
|---|---|---|---|
| HUNGER_GAMES | 86,5 % | 4,0 % | 9,5 % |
| Классика | 82,8 % | 0 | 17,2 % |
| BIRD_BOX | 80,8 % | 0 | 19,2 % |
| SPEEDRUN | 80,2 % | 3,0 % | 16,8 % |
| DUEL | 79,2 % | 0 | 20,8 % |
| THREE_MUSKETEERS | 78,2 % | 0 | 21,8 % |
| OLD_SCHOOL | 78,2 % | 0 | 21,8 % |
| SCHRODINGER_SHIP | 74,2 % | 0 | 25,8 % |

Оговорка: перевес в модели — только в добивании. Перевес настоящего движка (карта вероятностей) другого рода, поэтому для ставки повторить то же с `ProbabilityBot` против Baseline: `python bench/protocol_bench.py --strategy battleships.strategies.contract:ProbabilityBot --strategy-b battleships.strategy:BaselineStrategy --reconnect 0 --opp-bonuses 0 -n 400 --modifier <режим>`.

- **«Голодные игры».** Цель — попадания за 40 выстрелов, а не потопление. Добивание здесь ценнее всего (модель: 86,5 % — лучший режим, расхождение с классикой в пределах шума). Всегда бить в клетку с наибольшей вероятностью, без шахматного поиска. `SUNK` объявляется, «подтверждать» нечего. Расстановка: корабли туда, куда карты вероятностей стреляют последними (края, углы) — сопернику достанется меньше попаданий за 40 выстрелов. По анализу Дианы здесь окупается SHIELD.
- **«Спидран».** Важно только число выстрелов, расстановки нет. Флот строится как у встроенного `HARD`: каждая выигранная тренировка против `HARD` раскрывает его флот целиком (все клетки `HIT`/`SUNK` в нашем JSONL-логе). Собрать априорную карту и подмешать её к карте вероятностей. Отвечать можно дольше 150 мс: соперник не ждёт, но держать запас до 0,75 с. Любой обрыв стоит выстрелов, отсюда пинг 5 + 5 с.
- **«Дуэль».** Цель та же, что в классике (меньше промахов до потопления), 58,0 выстрела на флот в обоих режимах. Менять ничего не нужно.
- **«Корабль Шрёдингера».** Самый дорогой режим: без вывода потопления +9,9 выстрела на флот, перевес в меткости съедается сильнее всего (74,2 %). Вывести потопление точно: выборкой целых флотов, согласованных с известным (шаг 3 HANDOFF). При неоднозначности выбирать выстрел, который одновременно продлевает отрезок и закрывает его конец. При пустой карте стрелять в любую допустимую клетку, а не бросать исключение.
- **«Казино».** По модели сильнее всего «Голодные игры» и классические режимы, слабее всего «Шрёдингер». Если наш точный вывод потопления окажется лучше, чем у соперников, картина может перевернуться — проверить прогоном выше. Не ставивший проигрывает любой ставке, поэтому минимальная ставка (0,1, если её примут) почти бесплатно выбирает режим. Ставка списывается всегда; решение за Дианой.
