# Хаки: серия по приросту рейтинга и Голодные игры

10.10.2026, около 19:03 UTC+05 (17:03 МСК). Только Хаки Наблюдения,
ID `6603c7b8-f81d-4309-b4cf-28e3f9a6c670`. Нагибатор228 не изменяется.

## Новое правило серии

Пользователь отменил остановку после двух поражений и подтвердил первые **3 матча**
без остановки по рейтингу. Перед подключением получаем стартовый рейтинг и
`matchCount` из API платформы. Сразу после каждого завершённого матча закрываем игровой WebSocket, затем запрашиваем
свежие значения; после третьего и далее продолжаем только при `rating > ratingBefore`.
При нулевом или отрицательном приросте не подключаемся снова. При положительном
приросте (или до третьего матча) открываем новое соединение с прежней базой рейтинга. Это сравнение с началом всей серии, не с прошлым матчем и не с максимумом.
Два, три и больше поражений сами по себе не останавливают серию при положительном приросте.

Контроль находится внутри клиента, поэтому закрытие вкладки или панели его не отключает.
Панель передаёт `HAKI_STOP_POLICY=RATING_GAIN`, `HAKI_RATING_WARMUP=3`. Старый режим
ручного CLI без этих переменных сохраняет прежний лимит поражений. Панель показывает
начальный рейтинг, последний подтверждённый рейтинг и решение после матча.

Статистика должна включать все завершённые матчи серии: проверяем `matchCount`.
Если API не успел обновиться, ждём ограниченное время (3 секунды плюс текущий HTTP-запрос
до 1,5 секунды). При отсутствии подтверждённого рейтинга останавливаемся с
`RATING_UNAVAILABLE`; до подключения при недоступном API запуск не начинается.
Штрафы за бонусы и простой входят в фактический рейтинг платформы, отдельно их не угадываем.
Порог проверяется между матчами, поэтому проигранная партия может опустить итог ниже нуля.

Кнопки «Остановить после матча» и «Аварийная остановка» сохранены. Аварийная остановка
может привести к техническому поражению текущей партии. После остановки автоперезапуска нет.

## Подготовка к Голодным играм

Объявление организатора: в 17:00 МСК вместо Шрёдингера включается HUNGER_GAMES
с 20 выстрелами. Активацию определяем по MATCH_STARTED, не по часам клиента.
Клиент уже принимает shotLimitPerPlayer и shotsLeft от платформы; 100 не навязывается.
При лимите победитель определяется попаданиями (protocol-reference.md, раздел лимитов).
Для Хаки отключён DISTANCE в HUNGER_GAMES либо при лимите ≤20: бонус расходует выстрел,
а окупаемость на таком коротком горизонте не подтверждена. Поиск и добивание сохранены.
При новом модификаторе потопления снова учитываются обычным способом. Эксперимент
четырёх оставшихся кораблей остаётся выключенным. Симуляторный пресет команды на 40
выстрелов не менялся; тест Хаки явно задаёт 20. Это подготовка, не доказательство
роста доли побед.

## Проверки

Регрессионные сценарии: первые два минуса не останавливают серию; положительный итог
после третьего матча продолжает её; нулевой итог останавливает. Устаревший matchCount
не принимается за свежий рейтинг. Отдельный WebSocket-тест проходит два поражения,
победу и ещё поражение; HTTP-проверка начинается только после закрытия WebSocket; при нулевом итоге пятого подключения нет.
Проверка HUNGER_GAMES задаёт 20 выстрелов и запрещает расход DISTANCE.
