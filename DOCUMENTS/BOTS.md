# Два бота команды: стратегии и запуск

**Хаки, обновление 10.10.2026 17:48 UTC+05:** [поддержка Шрёдингера и защита против мин](HAKI-SCHRODINGER-2026-10-10.md).
Предыдущее дополнение: [ранний DISTANCE и история соперников](HAKI-MEMORY-2026-10-10.md).
Это актуальная конфигурация Хаки; прежние сравнения ниже описывают историю разработки.

Назначение стратегий согласовано с Музробом 10.10.2026. Это конфигурация запуска,
а не индикатор работающих процессов. Обновление Git не запускает бота и не
заменяет код уже работающего процесса.

| Бот | Кто запускает | ID на платформе | Класс стратегии |
|---|---|---|---|
| Нагибатор228 | Борис | `44ad0176-01e9-47bf-a7f0-be7342a30cd9` | `battleships.strategies.contract:ProbabilityBot` |
| Хаки Наблюдения | Музроб | `6603c7b8-f81d-4309-b4cf-28e3f9a6c670` | `battleships.strategies.haki:HakiObservationBot` |

## Общая основа

- Одна оболочка WebSocket: события, лимиты, восстановление, проверка действий.
- Карта допустимых положений кораблей и добивание попаданий.
- Расстановка и поправка на края по профилю соперника из `scouting/profiles.json`.
- «Дуэль»: следующий выстрел только по запросу сервера.
- Хаки теперь умеет DISTANCE (до двух запросов); актуальные ограничения описаны по ссылке выше.

## Отличие Хаки Наблюдения

Актуальное дополнение от 10.10.2026: [отдельная защита Хаки против команд,
проверенные правила, время и тесты](HAKI-2026-10-10.md). Оно учитывает новую
общую основу после PR #12; описанные ниже исходные сравнения относятся к PR #11.

Когда остались только однопалубные и нет недобитого попадания, бот перебирает
совместимые положения всех оставшихся одиночек. Учитывает промахи, потопленные
корабли, запрет касания, включая углы, и существующую поправку на край.
Выбирает клетку с наибольшим суммарным весом совместимых расстановок; равные
варианты разрешает случайно. Вес расстановки — произведение весов её клеток:
это точный расчёт внутри выбранной модели, не знание привычек соперника.

У «Нагибатора228» сохраняется прежний расчёт отдельных положений: с нейтральным
профилем одиночки ищутся равновероятно среди допустимых клеток. Его класс не меняется.

Лимиты нового расчёта: до 40 мс (меньше при небольшом остатке бюджета),
100 000 сочетаний и 100 000 узлов. При превышении лимита или противоречивой модели
используется прежняя карта вероятностей. Частичный перебор отбрасывается, чтобы
не давать преимущество клеткам из-за порядка перебора. Отбитое щитом попадание
сохраняет приоритет для повторного выстрела.

Предварительный разбор 15 концовок, по 100 прогонов на позицию, дал сокращение
остатка поиска примерно с 13,7 до 13,0 выстрела для совместного расчёта без новой
поправки на край. Это уже изученные партии, не независимая оценка доли побед.
Новый вариант экспериментальный; турнирные результаты собираем отдельно.

На 200 новых случайных полях среднее число выстрелов: прежний расчёт 54,995,
новый 54,765. В 200 симуляциях «Дуэли» новый выиграл 97 раз, прежний — 103.
Убедительного роста доли побед нет; в этих проверках у обоих случайная расстановка
без профиля конкретного противника и без бонусов. Для воспроизведения:

```powershell
.\.venv\Scripts\python.exe scripts/benchmark_haki.py --games 200
```

## Запуск Хаки Наблюдения

В локальном `.env.muzrob` хранится `BATTLESHIPS_TOKEN_MUZROB` именно этого бота.
Файл и значение токена не коммитить. Из корня репозитория в PowerShell:

```powershell
.\scripts\run-haki.ps1
```

С 10.10.2026, 14:42 МСК, обычный запуск сначала запрашивает `TRAINING / EASY`.
После трёх тренировочных побед автоматически запрашивает `RANKING` в том же
соединении. Ничьи не считаются победами; поражение прекращает весь запуск.
Счётчик сохраняется при восстановлении соединения внутри процесса, но новый
ручной запуск снова начинает с тренировок. Это проверка работоспособности,
а не доказательство превосходства над турнирными соперниками.

По просьбе Музроба клиент останавливается при первом `MATCH_FINISHED` с
`outcome: LOSS`, включая техническое поражение. Победы и ничьи продолжают игру.
Отключение выполняет сам клиент; после поражения он не переподключается. В журнале
появляется `stop_on_loss`. Для точного класса `HakiObservationBot` правило обязательно
даже без флага `--stop-on-loss` в ручной команде. У остальных классов оно выключено
по умолчанию; поведение запуска Бориса не меняется.

Режим проверяется по `MODE_CHANGED`, тренировка дополнительно — по типу и уровню
соперника в `MATCH_STARTED`/`MATCH_SNAPSHOT`. Отказ переключения или 30 секунд без
сообщения при ожидании подтверждения/тренировки завершают запуск. Если уже идёт
партия, сначала доигрываем её и останавливаемся: разрыв соединения во время игры
сам по себе партию не отменяет. После подтверждения рейтингового режима ожидание
соперника не ограничивается этими 30 секундами.

Платформа начинает каждое подключение в `RANKING`, а `CHANGE_MODE` действует со
следующей партии. Поэтому уже назначенную первую рейтинговую партию предотвратить
клиентом нельзя; при таком несовпадении Хаки доиграет её и остановится. Это
ограничение протокола, не обещание строго тренировочной первой партии.

На момент проверки 14:35 МСК сайт показывал недавние тренировочные матчи MEDIUM
и HARD. Документация не даёт клиенту отдельного флага доступности тренировок или
кода `TRAINING_DISABLED`. Молчание сервера и ошибка режима не считаются доказательством
отключения тренировок. Если их отключение отдельно подтверждено, явный запуск:

```powershell
.\scripts\run-haki.ps1 -Mode RANKING
```

Первое поражение останавливает и такой запуск. Для другого тренировочного уровня:
`-Opponent MEDIUM` или `-Opponent HARD`; по умолчанию выбран EASY.

Для остановки после одной законченной партии:

```powershell
.\scripts\run-haki.ps1 -StopAfter 1
```

Эти команды подключаются к турниру и меняют рейтинг. При обновлении репозитория
они автоматически не выполняются. Скрипт закрепляет стратегию, переменную токена,
начальный режим `TRAINING` и отдельный журнал `logs/muzrob`. Эквивалент вручную:

```powershell
.\.venv\Scripts\python.exe -u -m battleships --env-file .env.muzrob --token-env BATTLESHIPS_TOKEN_MUZROB --strategy battleships.strategies.haki:HakiObservationBot --mode TRAINING --opponent EASY --log-dir logs/muzrob --stop-on-loss
```

## Запуск Нагибатора228

Борис использует свой локальный файл с токеном «Нагибатора228». Если он хранится
в стандартном `.env` под именем `BATTLESHIPS_TOKEN`, команда:

```powershell
.\.venv\Scripts\python.exe -u -m battleships --env-file .env --token-env BATTLESHIPS_TOKEN --strategy battleships.strategies.contract:ProbabilityBot --mode RANKING --log-dir logs/boris
```

Если имя файла или переменной у Бориса другое, сохраняем его значения. Фактическая
версия процесса Бориса с компьютера Музроба не подтверждается. Один токен
запускает только один ответственный участник.

В этой доработке исправлены правила допуска к рейтингу и остановки. Изменение
расстановки по профилям соперников объединено отдельно в PR №13; подробности

Новые проверки поднимают локальный WebSocket: три победы → рейтинг → поражение;
поражение на тренировке; отказ режима; отсутствие подтверждения; первая рейтинговая
партия, назначенная до переключения; сообщения следующего матча после остановки.
Проверено сохранение счётчика при переподключении и прежнее поведение другого класса.

## Объявленный переход в 15:00 МСК

По сообщению Музроба 10.10.2026 в 15:00 МСК планируется THREE_MUSKETEERS вместо
DUEL и пауза тренировок на 30 минут. Фактические правила каждой новой партии
берём из MATCH_STARTED, уже начавшуюся доигрываем по её правилам.

Для «Трёх мушкетёров» клиент отвечает отдельным выстрелом на каждый TURN_REQUESTED.
Попадание/потопление не уменьшает shotsLeftInTurn; промах уменьшает. Общий лимит
shotsLeft уменьшается и при попадании. Три выстрела сразу без запросов не отправляем.
Добавлена проверка именно с HakiObservationBot: переход DUEL → THREE_MUSKETEERS,
попадание, потопление, три промаха в одном ходу, без повторов и самовольных выстрелов.

Во время подтверждённой паузы тренировок оператор может использовать явный
`-Mode RANKING`; без такого выбора клиент не угадывает доступность по молчанию.
Первое поражение останавливает запуск и в новом модификаторе. Мониторинг правил
и Git сам по себе не запускает остановленного бота.
