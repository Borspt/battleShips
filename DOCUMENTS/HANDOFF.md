## Роли (из документа Дианы)

- **Борис — стратегия.** Стрельба по карте вероятностей, рандомизированная расстановка,
  адаптация к сопернику, офлайн-симулятор. Метрика — среднее число выстрелов до победы.
- **Музроб — интеграция и надёжность.** Обёртка над протоколом, модель состояния партии,
  переподключение, запасной ход при таймауте, логи, запуск. Метрика — ноль технических
  поражений.
- **Диана — продукт.** Регламент, приоритеты, внутренние турниры между версиями, разведка
  по логам, питч. Решает, какую версию выкатывать.

Контракт между стратегией и обёрткой, предложенный в документе (ещё не согласован):

```python
place_ships() -> list[ship]
next_shot(my_shots_history, opponent_info) -> (x, y)
on_result(x, y, result)  # мимо / ранил / убил
```

## Что из правил определяет архитектуру

- **Правила берутся из `MATCH_STARTED`, а не из кода.** Размер поля, состав флота,
  лимит выстрелов, выстрелов за ход, время на ход и модификатор приходят в каждой партии.
- **Корабли всегда прямые.** Протокол описывает флот как список «длина × количество».
  Фигуры произвольной формы, которые закладывал документ Дианы, не нужны.
- **Смена правил — это конечный список из восьми модификаторов**, они уже описаны в
  [rules.md](rules.md). Готовиться можно заранее, а не в 14:00.
- **На ход 1 с, пропуск засчитывается промахом.** Стратегия должна отвечать за десятки
  миллисекунд, а обёртка — иметь запасной ход.
- **Повторный выстрел и выстрел вне поля платформа молча считает промахом.** Проверка
  допустимости хода — на нашей стороне.
- **Тренировочные партии тоже меняют рейтинг** (K = 10). Проигрывать встроенным ботам
  не бесплатно.
- **Первые 10 рейтинговых партий идут с K = 40.** Выходить в рейтинг с сырым ботом вдвое
  дороже, чем потом.
- **При лимите выстрелов или времени побеждает тот, у кого больше попаданий.** В режиме
  «Голодные игры» (40 выстрелов) это основной исход.
- **Неизвестные сообщения и значения надо пропускать**, протокол расширяется на ходу.

## Как обновить сведения с платформы

Страницы сайта — одностраничное приложение, данные отдаёт API под сессией участника:

- вход: `POST /api/v1/session` с телом `{"login": "...", "password": "..."}`, сессия в cookie;
- действующие правила, цены бонусов, простой: `GET /api/v1/rules`;
- справочник сообщений: `GET /api/v1/documentation/protocol`;
- команда и боты: `GET /api/v1/teams/current`;
- лидерборд: `GET /api/v1/leaderboard`.

После смены правил в 14:00 перечитать `GET /api/v1/rules` и обновить `DOCUMENTS/rules.md`.
