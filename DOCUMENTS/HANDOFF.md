## Роли (из документа Дианы)

- **Борис — стратегия.** Стрельба по карте вероятностей, рандомизированная расстановка,
  адаптация к сопернику, офлайн-симулятор. Метрика — среднее число выстрелов до победы.
- **Музроб — интеграция и надёжность.** Обёртка над протоколом, модель состояния партии,
  переподключение, запасной ход при таймауте, логи, запуск. Метрика — ноль технических
  поражений.
- **Диана — продукт.** Регламент, приоритеты, внутренние турниры между версиями, разведка
  по логам, питч. Решает, какую версию выкатывать.

Контракт между стратегией и оболочкой задал Музроб: `docs/strategy-contract.md`.
Оболочка сама хранит состояние партии и при каждом вызове передаёт его целиком, стратегия
памяти между вызовами не держит:

```python
place_ships(rules) -> list[list[Cell]]
choose_action(state, time_budget_ms) -> Action   # до 150 мс на вызов
```

Наша стратегия подключается адаптером `battleships/strategies/contract.py`: он на каждый
вызов заново собирает знания из `state.shots`. Внутренний интерфейс ядра (`next_shot`,
`on_shot_result` в `battleships/strategies/base.py`) остаётся для симулятора.

## Что из правил определяет архитектуру

- **Правила берутся из `MATCH_STARTED`, а не из кода.** Размер поля, состав флота,
  лимит выстрелов, выстрелов за ход, время на ход и модификатор приходят в каждой партии.
- **Корабли всегда прямые.** Протокол описывает флот как список «длина × количество».
  Фигуры произвольной формы, которые закладывал документ Дианы, не нужны.
- **Смена правил — это конечный список из восьми модификаторов**, они уже описаны в
  [rules.md](rules.md). Готовиться можно заранее, а не в 14:00.
- **На ход 1 с, пропуск засчитывается промахом.** Стратегия должна отвечать за десятки
  миллисекунд, а обёртка — иметь запасной ход.
- **Повторный выстрел и выстрел вне поля платформа молча считает промахом.** Проверка
  допустимости хода — на нашей стороне.
- **Тренировочные партии тоже меняют рейтинг** (K = 10). Проигрывать встроенным ботам
  не бесплатно.
- **Первые 10 рейтинговых партий идут с K = 40.** Выходить в рейтинг с сырым ботом вдвое
  дороже, чем потом.
- **При лимите выстрелов или времени побеждает тот, у кого больше попаданий.** В режиме
  «Голодные игры» (40 выстрелов) это основной исход.
- **Неизвестные сообщения и значения надо пропускать**, протокол расширяется на ходу.

### Что известно о встроенном `HARD`

- **Расстановка.** Корабли длиннее одной клетки стоят вдоль краёв поля, однопалубные — внутри.

### Разведка: статистика по ботам

Платформа отдаёт участнику реплей любого завершённого матча, не только нашего:
`GET /api/v1/matches?page=N` — список, `GET /api/v1/matches/{id}` — расстановки обеих сторон
и все выстрелы. `battleships/scouting.py` скачивает новые матчи и собирает профиль каждого бота.

```
python -m battleships.scouting              # докачать новые матчи, пересобрать профили, таблица
python -m battleships.scouting --offline    # без сети, из уже скачанного
python -m battleships.scouting --bot Stefan # карточка бота: карта расстановок и дебютных выстрелов
```

- Нужны `BATTLESHIPS_LOGIN` и `BATTLESHIPS_PASSWORD` в `.env` — учётная запись участника.
- Профили лежат в `scouting/profiles.json` — файл в репозитории, чтобы они были у всей команды.
  После запуска разведки его надо закоммитить и запушить.
- Скачанные реплеи и лидерборд лежат в `runtime/scouting/` (в `.gitignore`, десятки мегабайт).
  Профили пересобираются из реплеев на диске: у кого их меньше, тот при запуске разведки
  перезапишет общий файл более бедным. Договориться, кто один ведёт разведку.
- Разведка качает матчи от новых к старым и останавливается на первой уже скачанной странице;
  `--full` проходит весь список.
- В профиле: последний рейтинг, матчи и победы, личные встречи с нами, доля клеток длинных
  кораблей у края, доля однопалубных у края, число разных расстановок, карта расстановок по
  клеткам, доля дебютных выстрелов у края, среднее число выстрелов до потопления флота.
- Для выбора стратегии под соперника: `load_profiles()` и
  `profile_for(profiles, state.opponent_info)`; ключ тот же, что `opponent_info.key` в оболочке:
  `bot:<UUID>` или `builtin:HARD`. Текущий рейтинг соперника оболочка кладёт в
  `state.opponent_info.rating` (контракт версии 2, `docs/strategy-contract.md`).

### Запись выбранного плана

`ProbabilityBot` в начале каждой партии дописывает строку в `logs/plans.jsonl`: время, ключ и
рейтинг соперника, модификатор, расстановка, поправка в стрельбе и причина выбора. Файл
локальный (в `.gitignore`), он остаётся на машине, где запущен бот.

```
python -m battleships.scouting --plans
```

Команда сводит записи с исходами матчей нашей команды из скачанных реплеев: сколько партий
сыграно каждым планом и сколько выиграно. Пара «запись — матч» ищется по ключу соперника и
времени, поэтому перед этим нужно обновить разведку.

### Чего нет

- Партий между ботами команд почти нет, поэтому против большинства соперников план пока
  нейтральный. Он начнёт меняться, когда пойдут рейтинговые партии и разведка их скачает.
- Профили обновляются только запуском `python -m battleships.scouting` и коммитом
  `scouting/profiles.json`; бот перечитывает файл сам, когда он изменился.
- Половина выстрелов уходит на поиск четырёх однопалубных.
- Бонусы и ставки не используются; в симуляторе бонусы не моделируются.

   стратегией играть рейтинг. У «Нагибатора228» первые 10 рейтинговых партий пойдут с K = 40.
2. Выяснить, какой стратегией играет «Хаки Наблюдения»: `ProbabilityBot` или запасной
   `BaselineStrategy` оболочки.
3. Обновлять разведку и коммитить `scouting/profiles.json`, пока идут рейтинговые партии.
4. Бонусы: Диана рекомендует `DISTANCE` ×3; бот бонусами не пользуется, симулятор их не моделирует.
5. Следить за сменой модификатора: `GET /api/v1/rules`.
6. Добавить `certifi` в `requirements.txt` и подхватывать его в клиенте.
